# dependency-risk-score\n\nProblem: Teams pick and keep dependencies without a consistent view of which ones are abandoned, single-maintainer, vulnerable or copyleft, and each review weighs these differently. This library turns a facts file gathered by any tool into one explainable 0-100 risk score per package with fixed, overridable weights and named reasons.\n\n## Installation\n\nInstall via pip or your preferred package manager (uv add dependency-risk-score).\n\n## Usage\n\n```python\nfrom datetime import date\nfrom dependency_risk_score import Package, Vulnerability, score_package\n\npkg = Package(\n    name="example", version="1.0.0", last_release=date(2023, 1, 1),\n    maintainers=1, license="GPL-3.0-only",\n    vulnerabilities=(Vulnerability(id="GHSA-1", severity="high"),)\n)\nreport = score_package(pkg, as_of=date(2026, 11, 6))\nprint(f"{report.score} {report.level}: {','.join(report.reasons)}")\n```\n\n## API Summary\n\n- `load_facts(text: str, *, max_bytes: int = 5_242_880, max_packages: int = 10_000) -> list[Package]`: Parses JSON facts. Raises `RiskError` (invalid_facts, input_too_large, invalid_date) for structural errors or exceeded limits.\n- `score_package(pkg: Package, *, as_of: date, weights: Weights = DEFAULT_WEIGHTS, licenses: Mapping[str, str] = DEFAULT_LICENSES) -> RiskReport`: Scores a single package based on eight rules: release aging/staleness, single maintainer, deprecation, license category, and vulnerabilities (capped).\n- `score_all(pkgs: list[Package], *, as_of: date, ...) -> list[RiskReport]`: Scores a collection and sorts by descending score, then ascending name.\n- `Weights`: Frozen dataclass (critical, high, medium, low, vuln_cap, aging, stale, single_maintainer, deprecated, weak_copyleft, strong_copyleft, unknown_license). All fields must be integers 0-100 (bools are rejected).\n\n## Why not OpenSSF Scorecard?\n\nOpenSSF Scorecard performs online repository analysis. `dependency-risk-score` provides offline, deterministic scoring over facts you have already gathered (e.g., from an SBOM or local scanner).\n\n## Security\n\nSee [docs/SECURITY.md](docs/SECURITY.md) for threat modeling and resource limits.
